# كواليس الصين — نظام إدارة طلبات التوريد (MVP)

**Kawalis China — China Sourcing Request Management MVP**

- **الموقع** = واجهة العميل (طلب توريد + تتبع الطلب + العروض المعتمدة)
- **Notion** = نظام التشغيل الداخلي والمصدر الوحيد للحقيقة (SSOT)
- **Notion API** = طبقة الربط (server-side فقط)

## هيكل المشروع

```

  dto.ts                  whitelist للحقول المرئية للعميل
  validation.ts           Zod schemas + توحيد أرقام الجوال
  statuses.ts             حالات الطلب الـ 24

```

## التشغيل محلياً

```bash
# 1. التبعيات
npm install

# 2. البيئة
cp .env.example .env.local
# عبّئ NOTION_API_KEY ومعرفات القواعد الأربع (انظر NOTION_SETUP.md)

# 3. تحقق من إعداد Notion
npm run validate:notion

# 4. شغّل
npm run dev
# http://localhost:3000
```

## النشر على Vercel

1. اربط المستودع بمشروع جديد في Vercel (إعدادات Next.js الافتراضية تكفي).
2. أضف متغيرات البيئة في **Settings → Environment Variables**:
   `NOTION_API_KEY`، معرفات القواعد الأربع، `WHATSAPP_NUMBER`،
   `NEXT_PUBLIC_WHATSAPP_NUMBER`.
3. لرفع الصور: **Storage → Create Blob Store** واربطه بالمشروع
   (يضيف `BLOB_READ_WRITE_TOKEN` تلقائياً). بدونه يعمل كل شيء عدا رفع الصور.
4. Deploy، ثم أرسل طلباً تجريبياً وتأكد من وصوله إلى Notion.

## قائمة الفحص الأمني

- [x] `NOTION_API_KEY` server-side فقط — لا يصل للمتصفح أبداً
- [x] كل عمليات Notion في `lib/notion.ts` (server only)
- [x] التتبع يتطلب رقم الطلب **+** جوال أو بريد مطابق
- [x] رسالة خطأ واحدة للفشل — لا نكشف هل الرقم موجود أصلاً
- [x] DTO whitelist — لا يُعاد أي حقل غير مصرح به للعميل
- [x] العروض تظهر فقط عند تفعيل `Approved For Customer`
- [x] رد العميل على عرض يتحقق أن العرض معتمد وتابع لطلبه
- [x] Zod validation على كل مدخلات الـ API
- [x] Rate limiting + منع إرسال مكرر (submission token)
- [x] رفع الملفات: صور فقط، حد 5MB، أسماء عشوائية
- [x] الأخطاء التقنية تُسجل server-side ولا تظهر للعميل

## قائمة فحص الاختبار

- [ ] إرسال طلب كامل → يظهر في Notion بحالة `01 — طلب جديد` + سجل Communications
- [ ] إرسال بدون حقول إلزامية → رسائل خطأ عربية واضحة
- [ ] ضغط إرسال مرتين → الطلب الثاني يُرفض (409)
- [ ] تتبع برقم طلب صحيح + جوال صحيح → تظهر الحالة والخط الزمني
- [ ] تتبع برقم صحيح + جوال خاطئ → رسالة "لم نجد طلباً مطابقاً"
- [ ] عرض بدون `Approved For Customer` → لا يظهر للعميل
- [ ] تفعيل الاعتماد → يظهر العرض ببيانات العميل فقط (بدون بيانات المورد)
- [ ] "اختيار هذا العرض" → `Is Selected Quote` ✓ وحالة الطلب `12`
- [ ] تغيير حالة الطلب في Notion → الخط الزمني يتحدث في صفحة التتبع

## خارطة الطريق المستقبلية

1. **إشعارات**: بريد للفريق عند كل طلب جديد (Resend)، ثم WhatsApp Business API
   للعميل (تأكيد الاستلام، تحديث الحالة، توفر عروض).
2. **حسابات عملاء**: تسجيل دخول برقم الجوال (OTP) ولوحة بكل طلبات العميل.
3. **مقارنة عروض تفاعلية**: جدول مقارنة جنباً إلى جنب مع تصدير PDF.
4. **لوحة فريق خارج Notion** عند تجاوز حجم العمليات قدرات Notion.
5. **لغة إنجليزية**: البنية جاهزة (النصوص قابلة للفصل إلى ملفات ترجمة).
6. **مدفوعات**: تسجيل الدفعات وربطها بالطلبات.

## قاعدة التشغيل الذهبية

> الموقع للعميل، وNotion للفريق. أي معلومة داخلية (ملاحظات، هوامش، بيانات
> موردين، تفاوض) تبقى في Notion ولا تعبر أبداً إلى الواجهة إلا عبر حقلي
> `Customer Visible Update` و`Customer Visible Notes` وبقرار صريح من الفريق.
